Triage the GitHub issue the user passed with the invocation (a URL or `#n`). No issue
given: ask for one. Treat the issue as **stale**: every claim in it is checked against the
current code, docs and sibling issues before it is trusted.

Rules for every GitHub write: [tickets](../../../docs/tickets.md) and
[triage labels](../../../docs/triage-labels.md). Every comment and issue body you write
starts with `> *This was generated by AI during triage.*`. Precedent for a split: parent
#218 (`tracking-only`) with slices #227 (design), #230 (backend), #231 (frontend).

## Steps

1. **Gather context.** Read the issue, its comments, blockers, parent and siblings
   (commands in [tickets](../../../docs/tickets.md#selecting-work)), every spec section it
   cites, [GLOSSARY.md](../../../GLOSSARY.md), and the code that already implements nearby
   behavior. Note what is stale: shipped already, owned elsewhere, contradicted by the spec.
   Then give a brief recommendation: labels, size, stale parts, open questions.
   _Done when_ the recommendation is posted to the user and every stale claim is named with
   its source.

2. **Grill.** Use the `grilling` and `domain-modeling` skills, one round at a time. Look up
   facts yourself; ask the user only for **decisions**. Write each question in plain words:
   short sentences, everyday language, one decision per question, a concrete example, and
   your recommended answer. Edit GLOSSARY.md in place as terms settle; leave it
   uncommitted.
   _Done when_ you list the decisions made and the user confirms nothing is open.

3. **Structure.** Split when the work exceeds five acceptance criteria or one fresh context
   window: a `tracking-only` parent plus design, backend and frontend slices as the work
   needs (shape and ownership in [tickets](../../../docs/tickets.md#shape)). Show the full
   **write plan**: every issue's title, body, labels, milestone, Priority, parent and
   blockers; the parent rewrite; the decisions comment; the spec doc and GLOSSARY.md diffs;
   the docs commit message. Then stop and wait.
   _Done when_ the user approves the plan. Any change request means a revised plan and
   another wait.

4. **Push.** The approval authorizes exactly the plan. Create slices blockers-first so each
   blocked-by link targets an existing issue, per
   [tickets](../../../docs/tickets.md#creating). Rewrite the parent as `tracking-only`
   (slice table, shared rules, sole criterion: slices closed). Post the decisions comment
   on the parent. Add the new rules to the spec doc, then commit it with GLOSSARY.md per
   [commits](../../../docs/commits.md) and push to main.
   _Done when_ every write is read back (`gh issue view`, `git show --stat`) and matches
   the plan.

Report: issues created or rewritten (`#n`), commit, anything that failed.
