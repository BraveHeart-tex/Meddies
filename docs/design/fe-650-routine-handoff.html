Meddies routine review and handoff

A cross-check of the four approved designs (FE-646 to FE-649) as one routine: sign in, add a medicine, schedule it, record and correct doses, check History, sign out. It lists every surface and the frame that covers it, the drift between journeys and how to correct it, and which implementation issue takes each part. Synthetic data, Fri 6 Nov 2026, Istanbul time.

Decisions

Each one comes from drift between the approved designs and production, or a surface no design covers. Bora accepted all four as recommended on 6 Nov 2026. None changes PRODUCT.md or FE-612.

D20

Due now badge: blush, as in production

FE-646 and production (Badge variant="due") use a blush fill with berry text. FE-648 and FE-649 mocks drew it as a solid berry fill with white text. The kit reserves berry for one primary action per view, and the Today hero already has a berry "Taken" button, so a berry badge competes with it. Inside the blush Up next card a blush badge would disappear, so there the status sits in the card's eyebrow instead.

Accepted: keep production due (blush, berry-ink, clock icon) on rows and drawer chips. In the Up next card, show the status as the eyebrow "Due now · 14:00" with the clock icon, with no badge. FE-648 screens are read with this change.
Alternative: adopt the berry fill from FE-648 and change the production variant. Status gets louder, and two berry elements sit in the same view.
D21

New variants: two Badge variants, no new Alert variants

FE-648 approved one new Badge pending variant, but its mocks draw two looks: neutral dashed for Saving and amber dashed for Not confirmed. FE-647, FE-648 and FE-649 also use info and warning Alerts (session ended, signed out, recorded elsewhere, D18 sign-out warning, sign-in unavailable). Production Alert has only default, confirmation and destructive, so FE-649's "no new variants" was not accurate.

Accepted: add Badge pending (neutral dashed, Saving) and unconfirmed (amber dashed with warning icon, Not confirmed). Both reuse existing tokens; they are separate because Not confirmed needs her attention and Saving does not. Map info and warning Alerts to Alert default with the info or warning icon. Amber stays a dose and stock status color and does not become a general alert color.
Alternative: also add Alert warning (amber fill) for D18 and sign-in unavailable. Louder, but it reuses Not logged's color for a different meaning.

D22

Known offline: the same rule for every write

FE-648 replaces the drawer's Save with a disabled Connect to save and a one-line Alert when the device is known to be offline. FE-647's medicine and schedule forms and FE-649's Sign out have no such state, so the same situation reads differently by screen. "Known offline" means the browser reports no network. When it reports a network, the normal failure and uncertain-receipt paths still apply.

Accepted: use one rule for every write (dose, medicine, schedule, sign-out). While known offline, the primary becomes disabled "Connect to save" (or "Connect to sign out"), an Alert says "You're offline. Your details stay here until you leave this page." and values stay in the in-session draft. It returns to normal on reconnect, with no automatic save. Owners: FE-641, FE-643, FE-627.
Alternative: drawer only, as approved. Setup forms then show the "couldn't save" failure (647·M3) after a tap that could not have worked.
D23

A not-found page for unknown addresses

No design covers an address outside the app, such as an old link or a typo. src/app has no not-found.tsx and no global-error.tsx, so she would see Next.js's unstyled default 404, and a root layout failure would show the browser's default page. Unknown medicine IDs are already covered (647·D2).

Accepted: one themed not-found page built from the 649·L3 error pattern: "This page isn't in Meddies." with "Open Today". It shows no private content, so it is the same signed in or out. Add a minimal global-error with the L3 copy. Owner: FE-627 (bounded access audit), no new ticket.
Alternative: record it as a known gap for a later wave.

Product truth across the routine

Holds in every journey

  • ✓Scheduled time stays in the time column; actual intake appears only on the badge and intake line.
  • ✓Every outcome is an explicit Taken or Skipped choice; nothing preselected from a row.
  • ✓"Not logged", never "Missed" or "Overdue". No streaks, exclamation marks or emoji.
  • ✓Dose saves show Saving until the server confirms; setup saves wait for confirmation before the page changes.

Recovery and session

  • ✓Uncertain saves keep details and request identity for the session; Retry never creates a second record.
  • ✓Writes need a connection; no queued writes or stored drafts are shown or implied.
  • ✓Session end and sign-out clear private data; pending saves read "in progress", never "cancelled".
  • ✓Known offline follows one rule for every write (D22).
